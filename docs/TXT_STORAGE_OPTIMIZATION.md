# TXT 临时数据与坐标索引优化（本地未原生验证）

基线源码为 `86bd9676a1f06aacfffe392fd3c56f7946c2e30c`。已有性能结果保留不动；本批不提交、不推送、不访问远端、不运行 CI，不修改生产以外的性能样本/计时、工作流或 UI。以下是源码分配路径与预期变化，不是实测收益。

- 解码在原始不可变 Data 的同步借用字节缓冲上推进逻辑 chunk 边界；跨 chunk 不完整标量保留其起始位置，等下一块增加可见长度。不再复制整书 `[UInt8]`，也不保存逐标量 `Unit/String` 数组。每个有效标量直接追加到规范化 String，最多暂存一个 CR 的原始字节长度，CRLF 只产生一个映射步。
- 自动识别仍依次完整验证 UTF-8、GB18030、GBK，保持首个有效候选优先及兼容列表顺序。仅该候选建立索引，其他候选只产生临时规范化文本并在处理后释放。用 UTF-8 单元逐一比较，避免 Swift String 的规范等价比较；差异出现后才生成原有前 80 个字素预览。仍可能同时存活选定文本与一个临时候选文本，不是零复制或常量内存解码。
- 索引保存每个规范化标量的原始 byte 宽度及 UTF-16 宽度（1–2），打包为 1 字节；单个编码标量最多 4 字节，索引允许合并 CRLF 后最多 8 字节，不额外收窄编码器接受范围。每 256 步保存绝对双坐标。查询先二分检查点，再最多扫描 256 步，仍仅接受精确边界。64 位下元素载荷约 `N + 16*(floor(N/256)+1)` 字节，旧全表约 `16*(N+1)`；这不包含数组容量、容器、分配器等，不能换算成进程 RSS 降幅。
- `boundaryCount`、`utf16Count` 为常数时间；`boundaries` 保留兼容，但每次访问都会以 O(N) 时间新建完整 `[TXTBoundary]`。正常文档长度、分章和分页不得调用它；小型回归会显式调用它验证兼容结果，不增加缓存。
- 文档 ID 仍是原始 Data 的 SHA-256。版本 ID 的原始哈希字节仍为 `documentID|encoding.rawValue|scalar-newline-lf-v1|` 后接规范化 UTF-8。增量更新哈希，连续 UTF-8 直接同步借用；非连续存储回退最多 64 KiB 缓冲，不拼接整书哈希 Data。
- 分章以相同 LF 规则逐行扫描，不再一次保存全部行 Substring；原正则、空白处理、前言和章节范围/ID 规则不变。分页字素边界逻辑、TXTProcessor actor 隔离、严格 GBK/GB18030 转换及损坏输入拒绝规则保持。

新增 6 项回归：混合 Unicode/CRLF 的 UTF-8 与 UTF-16 分块、跨检查点随机双向映射和范围、GBK/GB18030 宽度、五种编码的固定旧版本 ID、候选晚失败/预览之后差异、逐行分章空行及末章覆盖。旧 19 项测试文件和断言原样保留。固定版本 ID 用少量合成字节及公开 SHA-256 拼接规则独立计算，不能当作 Swift 或 iOS 编解码通过证据。

风险是新索引查询的有界局部扫描成本、chunk/CR 暂存状态、CryptoKit 指针更新及 Swift 6 编译兼容性。Windows 无 Swift/Xcode，本地仅能做范围/源码静检和小型参考核验，不能宣布原生编译、回归或内存收益通过。
