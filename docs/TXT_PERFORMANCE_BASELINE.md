# TXT 大文件合成基线

独立手动 `txt-core-performance.yml` 工作流只运行 `TXTCorePerformanceTests` 的 **1 个 Swift Testing 测试**。该测试顺序尝试 10 MiB（10,485,760 字节）、50 MiB（52,428,800 字节），不是两个独立测试；本轮不运行原有 19 项功能回归。生产源码不变。

使用 macos-15 / Xcode 16.4 build 16F6 / XcodeGen 2.46.0，实际已有的 iOS 模拟器，Release / Swift `-O`。工作流保存工具链、模拟器 OS / SDK / UDID / 架构、源提交与有效编译配置。此数据不能代表 iPhone 13 / iOS 16.6.1 真机成绩，也不是秒开或大文件性能验收。

## 样本与生命周期

`chinese-chapters-v1`：无 BOM UTF-8。重复区块为 `第1章 基线\n` 加 1,024 行 `山河清朗，书页记录晨光与行旅。\n`。先放完整区块，再放完整正文行，最后以 ASCII 空格补足目标字节数；不截断多字节字符。实际字节数、预期章节/UTF-16 数及 SHA-256 在运行时记录。只生成合成数据，不提交或保存大样本文件。

生成、SHA-256 和报告写入不在解码计时内。调用 `TXTProcessor.decode(sample.bytes)`，使用默认 `using: nil` 自动识别及默认 chunk size；其内部全部工作计入解码。随后单独计时 `chapters(in:)`；不测分页或阅读 UI。以 `ContinuousClock` 记录含 actor 调度等待的单调 wall time，计时结束后才写报告。

两个尺寸在同一 test-host 进程串行运行。阶段结束时，原始 Data、文档/映射、章节结果均保活；该尺寸辅助函数返回后才开始下个尺寸。不会清空分配器或系统缓存，也不声称独立冷启动。fixture_ready 记录生成后、解码前的 RSS 基线，夹具 Data 当时仍存活；分章前的文档、映射及原始字节仍存活。

## 内存及保护口径

Darwin `task_info(MACH_TASK_BASIC_INFO)` 的 `resident_size` 和 `resident_size_max` 单位均为字节。分别保留：阶段边界当前 RSS、目标每 100 ms 采样并合并边界所得的**观测最大 RSS**、系统记录的整个进程生命周期 RSS 高水位。报告包含内部采样次数、实际最大观测间隔；短阶段可能没有内部采样，观测最大值可能漏过瞬时峰值，不能当真实阶段峰值。生命周期高水位不可重置，包含框架启动、夹具生成、先前阶段/尺寸和缓存，不是每阶段独立峰值。未测 phys_footprint，也未据此推断手机可用内存。

保护阈值为 RSS 1,536 MiB、解码 120 秒、分章 60 秒；这些是停止保护线，不是验收线。结构化并发守护取消当前生产调用，依靠现有内核的取消检查退出；不改生产内核。采样有调度延迟，不能保证阻止所有瞬时 OOM。测试整体 8 分钟、原生运行器 600 秒、job 15 分钟作额外上限。

10 MiB 发生歧义、解码/分章/测量错误、超时或内存越线，立即退出，不开始 50 MiB。每个阶段开始及结束都同步写入模拟器临时 JSONL，并输出日志；运行器在结束/异常后仅从选定模拟器和 runner 临时目录收集合成小报告，保存部分数据。意外进程终止若缺少结束记录，该阶段耗时/峰值标为未知，不从边界值伪造。失败不自动修复、重推或重跑。

本次结果仅存本 run 的短期 artifact：`performance-report.json` / `.md`、`events.jsonl`、原始日志、原生退出码、xcresult 与运行环境。源码文档不预填成绩，也不为补成绩再推送。
