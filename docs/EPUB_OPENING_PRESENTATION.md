# EPUB 打开呈现与冷暖诊断（本地候选）

基线：`d5fde953ca544deaecace0434a45b014ebd630b0`，已交付0.2.14/build16。本批只做本地实现、检查及后续定向验证建议；不修改版本、工作流、依赖、缓存预算或存储格式，不代表新IPA已生成或真机已验收。

## 已知反馈与计时边界

用户反馈明显提速但仍能感知加载，给出的暖开摘要为：打开→章节就绪362ms，资源准备311ms，原书读取/完整SHA21ms，逐资源校验外层248ms，会话6ms，排版/恢复51ms；1678资源约37.6MB，Ready命中、无迁移，页面关闭复用3次/全文档加载1次。

注意：旧`warmResourceVerification`在Ready路径从`verifyNodes`之前起计时，包含nodes.bin校验、并行资源校验和调度等，248ms不是纯文件读取或纯SHA。原生历史事件与JS事件起点不同，不叠加为本次打开时间；ready不是像素首绘。该摘要不能代表冷启动分布或P95。

## 顺序与实现

1. **观测**：书架EPUB打开在取renderer之前记录用户动作时间；记录点击→加载开始、点击→章节就绪、点击→正文揭示后的显示帧机会。显示帧机会来自前台挂载、当前token且路由允许交互后两次CADisplayLink回调；探针不驱动导航、不设置ready、不延迟交互，也不是屏幕像素证明。无回执写“未取得”，不写0。重试/后台中断样本明确排除正常耗时统计。
2. **衔接**：路由发布后立刻启动同一个幂等load()，与现有系统fullScreenCover过渡并行；保留视图.task入口兼容直接宿主调用。短等待显示书名与简短状态，280ms后显示小进度指示，1秒后补充真实阶段和退出说明，不再出现短暂的大圆角加载卡片。不新增强制等待或固定长度入场动画，兼容原“减弱动态效果”设置。
3. **安全揭示**：首次打开时WebView保持挂载且可进行布局，但用当前阅读底色遮挡未确认内容；正式ready后立即撤罩。只影响首次打开，不遮挡后续正常字号重排/跨章原有页面。触摸和辅助功能均不得操作未ready正文。长等待仍可退出，错误立即进入原错误/重试路径。
4. **主题**：独立UserDefaults枚举hint仅提供首帧外观，上次成功读取或成功关闭时更新；不包含书籍ID/正文/进度，不写入LibraryStore偏好。正式打开后始终以当前数据库偏好覆盖。首次安装或无有效hint时用既有默认纸色，不声称首次使用也可提前知道数据库主题。
5. **分段**：资源校验补有界分段观测，区分路径/类型/大小、打开读取关闭、完整SHA及外层墙钟。各并发lane累计时间不能相加当总耗时或CPU时间。仍完整读取与校验所有资源；不跳过未访问章节，不用mtime或大小代替SHA，不改变4路并发和文件预算。

不新增正文截图缓存、不扩充renderer预算、不修改分页JS/邻章调度。邻章ready后补入是否造成可见抖动，应先用录屏/帧耗时验证；不为猜测风险延后预载或重构资源存储。

## 关闭App后稍慢：判断与依据

### 结束进程后重新启动

**机制上预期略慢，当前尚无该次冷开日志，不能定量判定用户这次增量是否正常。**

- `EPUBWarmRendererCache`是路由所有者的进程内对象。WebView/DOM/已解码图片不能跨App进程保存；新进程首次开书一般取不到停放renderer，需要创建WebView、加载文档、排版和定位。
- 元数据解码、规范指纹及按章内存缓存也会失去进程内命中；`metadataDecodeReused=false`或`noLeaseProof`本身不是损坏。
- Ready文件及数据库目录引用是持久化的。`acquireReady`可在entries为空时重新登记已有版本，验证原书、manifest、nodes和资源后恢复，不依赖parked WebView，不应仅因结束进程就反复解析/复制整书。
- `reconcileReady`每进程首次对引用目录做协调，属于额外准备工作；其后不会每次重复。OS文件页缓存是否命中不受App进程标记保证，所以“本进程首次”不等于硬件冷盘。
- 计时从点书开始，不含用户点击App图标到书架出现的App启动时间。

### 仅退到后台后返回

缓存明确不因后台通知主动清空。当前阅读会话会暂停/保存，返回后新建导航代号恢复位置，允许复用DOM。iOS内存警告、WebContent进程终止、缓存容量淘汰仍可能使缓存失效，这是合理回退，不应为保持命中而取消安全处理。

### 需要按异常追查的证据与修复方向

|观测|判断/建议|
|---|---|
|首次进程打开页面miss、文档加载1次，随后同进程命中；Ready无迁移|符合预期，不建议“修复”为跳过校验|
|已完成Ready迁移后，每次新进程仍迁移/重建|检查持久目录引用、事务发布与恢复失败原因；修复已证实的生命周期/完整性问题，保留原书和可靠进度，不清库重导入|
|同进程反复打开仍全文档加载，且非版本/尺寸/主题不匹配|对照本次takeMiss/takeInvalid/rejectBudget/processTerminated等原因定位；不能把历史原因列表中某个旧失败当作本次原因|
|资源准备接近暖开，但章节恢复明显增长|检查WebContent启动、当前章图片解码与布局；确认具体阶段后才考虑预热或减少首屏工作|
|资源准备增长，尤其路径/读盘阶段|比较同机同书多次冷暖分段；优先减少安全等价的重复文件操作，不盲目提高并发|
|ready很快，但录屏仍白闪/跳位或不能立即操作|属于呈现/布局衔接问题，结合显示帧机会与录屏检查，不能以ready宣称首绘通过|
