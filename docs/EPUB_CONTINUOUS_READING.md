# EPUB 连续跨章（本地候选，未发布）

## 本批范围

用户确认本批优先实现 EPUB 正文无缝衔接，保留上下滚动／左右分页选择；字体、背景自定义延期。本批基于 63a68c3 和上一批未提交的 20 个文件继续开发，不修改 TXT 内核、数据库格式、原书或历史 IPA，不提交／推送／运行 Actions。

与历史 `EPUB_PAGING.md` 的边界换章、以及 `EPUB_READING_MODES.md` 初版自动换章不同：正常跨章不调用 `turnChapter`、不替换 WebKit 文档、不使用截图掩盖换页。显式目录／链接跳转和错误重试仍是受控导航。

## 设计合同

- `EPUBChapterWindow` 在后台通过原有 `EPUBResourceStore` 验证长度、SHA、路径、符链后取得已净化的 XHTML。正文由隔离世界插入；不扩大 yjepub XHTML URL 准入、不开放网络／脚本／frame。
- 默认预载 5 章，布局不足两屏时每批增加 5 章，最多 64 章，避免连续一行短章形成无法继续滚动的短页面；不拼接整本长书。每章沿用 8 MiB XHTML 上限，窗口驻留原始 XHTML 合计最多 40 MiB，补章必须保持 spine 连续；这是逻辑输入预算，不是 RSS、临时解析副本或解码图像内存测量。
- 每章独立节点／fragment 命名空间，链接和图片按各自章节路径解析。图片就绪后再补入正文窗口；插入／回收离屏章节时保持可见文本的屏幕坐标。
- 纵向正文按自然流接续，边界可同时看到前章结尾与后章开头。横向仍使用真正 CSS 分栏，章节从新栏开始，继续向前翻页即可跨章。
- 预载结果只有渲染权限，没有进度写权限。真实可见定位进入另一章后，ViewModel 撤销旧 epoch、取得并就绪新章 token，再保存该实际定位；`preserveViewport` 请求只交接权限，不滚动恢复或重载。
- 资源旧 epoch URL 仍拒绝；已解码图像不重新赋值 src，避免每次交接重新请求／闪烁。异步预载按 session/epoch 取消；失败保留当前正文与已保存进度，给出可重试提示，不偷偷退回整页跳章。
- 字号／行距／主题及阅读方式切换继续按章节路径＋文本节点＋UTF-16 锚点恢复，不用屏幕页码保存位置。

## 验证要求与证据层次

本地可执行：生产 JS 合成检查、浏览器真实布局检查、源码测试身份检查、差异和受保护文件哈希核对。浏览器是 Chromium，不代表 iOS WebKit 或手势／惯性体验通过。

已补 Host/UI 的同文档跨章、加载次数、模式切换、旧回调与恢复断言；后续原生与真机验收应完整覆盖：
1. 跨章前后 document 与正文节点身份不变、`documentLoadCount` 不增加，无加载面板；章末与下章标题能同时进入视口。
2. 正向／反向跨章、水平翻一整屏且纵轴为零、模式切换保持锚点。
3. 连续多章后窗口保持默认 5 章／短章扩展最多 64 章及 40 MiB 预算；离屏回收后视口不跳动；短章、图片章、重复 ID／相对链接正确。
4. 首末章不循环；预载不提前推进进度；旧 epoch／旧窗口异步事件不能写入；退出重开恢复真正可见章节。
5. 非法资源、脚本／网络拒绝及 TXT 隔离维持原断言。

原 `epub-paging-6` 的源白名单及选择不足以覆盖本批和上一批缓存变更，不能直接沿用作本批资格。应另行确认同候选的受影响 Domain 开启／缓存／session／progress、EPUB Host 与 3 个 EPUB UI 的最小充分原生选择；不默认重跑全部 214 项。Windows 无 Swift/Xcode，本批不能宣称编译、WebKit、真机、性能或 IPA 已通过。最终本地结果见本批 artifacts 报告。

本批本地最终执行：16 项生产 JavaScript 合成／静态检查、11 组 Chromium 真实布局检查通过；包含 390×844、`application/xhtml+xml` MIME 的连续一行短章，预载不发出进度事件，图片加载失败保留现有窗口。修复了固定 5 章导致极短章无法继续滚动的问题。Swift 编译、原生测试、真机执行仍为 0。

真机验收建议：保留原安装数据，使用后续获准覆盖安装包。在章节末尾慢拖、快速甩动和反向拖动，确认下一章提前可见、手指不松开也能继续；横向在最后一页继续翻页；连续跨过至少 8 章并返回；短章／图片章重复该操作；跨章后立即退出和重开；最后切换方向与字号，核对同段位置。配合录屏检查正文轨迹、闪屏、停顿和回弹，而非只看标题变化。不得为此卸载、清库或强制重导入原书。
