# 派生存储第一批：历史设计快照

以下保留第一批接入前的设计与当时状态。第一批随后已在 `3de2758` 完成一次原生验证；第二批默认入口、有界阅读、缓存淘汰、会话合同及当前未原生验证状态见 [第二批接入说明](DERIVED_READING_INTEGRATION.md)。下文“当前不接 UI”“无 LRU”“待 78 项”等仅属于第一批历史范围。

基线 `630cc83d6134732d69155b0df294c6d1d95aaf52`。本批仅实现显式派生构建、打开、范围查询和恢复；不接入现有导入或阅读 UI，不改变选择器、严格解码算法、目录规则或现有 DocumentVersion。原 58 项测试文件和断言保留。

当前为 Windows 本地源码与回归准备；尚未 Swift/Xcode 编译或原生执行。新增测试的声明数量不代表通过数量。本批未运行 CI、性能测量或真机验收，用户当前 App 没有因此获得加速。

## 入口与所有权

- `LibraryService.buildDerivedBook(id:budget:)`：只读管理的私有 TXT，用原 `TXTProcessor` 固定编码完整解码、分章；核对原字节身份和既有版本，导出并校验后条件发布。
- `LibraryService.openDerivedBook(id:budget:rebuildIfNeeded:)`：始终顺序读取全部原字节做 SHA256。先按可信书籍长度快速拒绝变化，循环至多读取该长度再探测 1 字节并复查长度，避免持续追加造成无界扫描；长度检查不替代 SHA。源缺失或变化明确失败，不用缓存、大小或 mtime 掩盖。默认不自动构建；显式允许恢复时，打开失败最多构建一次再打开一次。
- `DerivedBookSource` actor：租用单一 generation；返回有限正文、精确双向坐标、全局字素起点或有限目录页，不返回全量 `TXTDocument`。调用者须 `close()`；析构只异步兜底释放遗忘的租约。
- `LibraryStore` actor：派生指针、构建代号、空间预留和读者租约的唯一 authority。`DerivedBookStorage` actor 负责重度导出。`DerivedPackReader` 和文件句柄只由其所属 actor 同步使用，无 `@unchecked Sendable`、MainActor I/O 或跨 actor 的 NSString/CoreText 对象。
- 原 `prepareImport/confirmImport/openBook`、原书 `commitImport` 和进度保存逻辑不调用新入口。新入口也不创建 reading session 或保存进度；后续 UI 接入仍须每次取得新 session、最新位置与设置。

## 单文件布局 v1

位置：应用自有 `Application Support/YueJing/Derived`，排除备份。stage 与最终文件处于同一目录，名称仅为应用生成的 UUID generation，后缀分别 `.stage`、`.pack`。缺失可重建，不能视此位置为永不丢失的保证。

所有载荷整数使用明确的无符号 64 位小端编码，不序列化 Swift 内存布局。转换到 Int、乘加、范围、文件长度均检查。4096 字节头仅容纳有界元数据，不保存全量坐标或目录。

| 顺序 | 实际内容 |
|---|---|
| 固定头 4096 B | 8 B magic `YJPACK01`、8 B JSON 长度、有界 sorted-key JSON、零填充 |
| 正文区 | 连续规范 UTF16LE；文件位置为区起点加全局 UTF16 offset 的两倍 |
| 宽度区 | 每规范标量 1 B，原编码 `(rawLength << 1) | (utf16Length - 1)` |
| 检查点区 | 每 256 标量 16 B：raw/UTF16 两个 UInt64，含起点和必要 EOF 检查点 |
| 字素区 | 每 8192 UTF16 单位一个 1032 B 记录：8 B 全局前驱＋1024 B 起点位图 |
| 目录区 | 每项 48 B：raw 起点/长度、UTF16 起点/长度、标题池 offset/字节长度；nil 长度为 UInt64.max |
| 标题池 | UTF8 标题，保留前言 nil 和原 chapter ID 计算规则 |
| 摘要表 | 每个载荷逻辑页 32 B SHA256，最后一页按实际长度计算 |

逻辑页为 16384 B，是格式校验/读取单位，不假定设备物理页大小。正文页可穿过代理对或字素；读取范围必须是合法映射边界，拼齐后严格验证 UTF16，不用有损替换。CRLF 仍为一个映射步，BOM 内部、代理中间和原编码单元内部仍拒绝坐标。

manifest 保存 schema、原 SHA/版本/编码/BOM/总量、六个连续不重叠区描述、原规范化版本、decoder/分章规则 revision、Foundation 字素生产环境标签和摘要表 SHA。schema 与解释规则独立于 DocumentVersion；不会把缓存格式拼进阅读版本。重建若算不出原版本，明确失败，绝不改书架版本或进度迎合新包。

GRDB `derivedArtifacts` 保存 bookID/versionID/generation、整个固定头的 SHA256 和实际文件字节数。固定头绑定摘要表，摘要表绑定正文、坐标、字素和目录所有载荷页。读取前验证元数据和摘要表，首次读取某页校验该页；缓存只保存已校验的不可变页。校验不等于证明解码器正确，导出关系依赖原算法和差分回归；也不抵御同时篡改数据库和包的写入者。

## 范围查询与全局边界

raw/UTF16 查询按文件中的检查点二分，只读取所需页和最多 256 宽度步，并检查该段终点；没有全量 widths 或 boundaries 数组。正文查询限定 UTF16 长度，目录限定条数；标题逐项读取，标题最多 80 UTF16 单位。摘要表是唯一整表读取的校验元数据，受独立 metadata 预算限制；它不是恒定空间。

字素位图在初次构建时由同一完整 NSString 生成。块首保存之前或当处的全局字素起点，长 RI 序列、ZWJ、组合记号及跨多页字素不依赖有限保护带猜测。`composedStart` 对任意合法查询位置返回原全局决定，EOF 返回全文尾。此批不改布局；第二批必须继续保留现有 `layoutCannotAdvance` 条件，不强切字素或改变前瞻语义。

## 发布、取消和恢复

1. Store 取得既有书和版本，分配 generation，记录预期旧指针及空间预留。新构建会使旧构建失去发布资格；旧写者保留自身预留直到结束，不能因迟到清除新预留。
2. 后台构建私有 stage，写载荷、摘要表和头，同步文件，并用生产读取器回读校验全部页。构建错误、取消、预算不足在进入发布前清除自己 stage。
3. Store 的短同步段验证当前构建/旧指针/书版本，同目录移动到独立 generation 文件，再进行 GRDB 条件指针事务；重度导出不在这段内。失败只处理本 generation，不覆盖既有文件。
4. 数据库提交之后即返回已发布事实；迟到取消不伪报未提交。原书提交始终与派生发布独立。

文件系统和 SQLite 不是共同原子事务。文件同步和同目录移动不构成所有断电场景的绝对耐久保证；恢复以“缓存可缺失”处理：

| 状态 | 动作 |
|---|---|
| 半写 stage／无 DB 指针 pack | 显式恢复时清理识别的孤儿普通文件 |
| DB 指针存在、文件缺失 | 条件删除指针；保持书、原件和进度 |
| 打开或读页发现坏包 | 仅条件失效所读 generation，关闭失败句柄；不清除已更新指针 |
| 原件缺失或 SHA 不符 | 明确失败，不用派生正文替代真源 |
| 读中失败 | 该句柄终止；调用者可显式重新打开并允许一次重建，无隐藏重试循环 |
| 旧读者仍租用 | 清理跳过其 generation，关闭后才可回收 |

`recoverDerivedStorage()` 是显式操作，不在原首屏/打开路径自动扫描。只对专用目录下 UUID.stage/UUID.pack 普通非符链文件操作，不递归删除，不触碰 Books、Imports、用户文件或进度。恢复开始前先成功打开数据库；未知命名项保留。单个 LibraryStore 是管理该根的唯一活动 authority，测试中新 Store 仅在旧写者停止后模拟内存状态丢失，不冒充真实进程杀/断电验收。

## 预算与空间不足

调用者必须显式提供单包上限、总派生存储上限、校验元数据上限、逻辑工作集上限、每次正文字数和目录条数；无隐式书籍大小限制或未测的用户硬配额。超预算仅拒绝本次派生操作，不删书、不自动淘汰当前有效指针，也不把请求悄悄放大成整书。

初次构建仍持有原完整 Data、String、索引、目录和可能的 NSString：**本批不是流式导入，也不保证构建峰值内存。** 读者工作集计账包括摘要表、页缓存和请求临时/返回数据的保守系数；真实容量、桥接、分配器及活动 UI 不等于此估算，须原生采样 RSS 验证。

空间预留按 caller 单包最大值保守计费，包含现有 pack、未完成构建及识别的孤儿文件；已 unlink 但仍由旧读者租用的 generation 继续计费，允许过渡时必须为新旧两代提供空间。当前只做 admission 和显式孤儿清理，**没有 LRU 自动淘汰或后台重试**。真实 ENOSPC/I/O 失败仍可发生，不能靠预检保证成功；本批故障注入验证失败不伤书/进度。

估算载荷：`2*UTF16Units + scalars + 16*(floor(scalars/256)+1) + 1032*ceil(UTF16Units/8192) + 48*chapters + titleUTF8Bytes`，另加 4096 B 头及每逻辑页 32 B 摘要。50MiB 纯 ASCII 的正文、映射、检查点和字素部分约 159.4MiB，目录、摘要、原件及旧 generation 另计；中文不能套用固定倍率。
